# DeepModel Insight 功能说明书

## 1. 产品概述

**DeepModel Insight**（Maven 坐标 `com.deepmodel:relation`）是面向 Q7Link / 企企 ERP **MDD 模型元数据**的分析工具。它连接租户 PostgreSQL 库，读取 `baseapp_object_field`、`baseapp_object_type` 等元数据表，在内存中构建字段依赖图，并提供 Web 可视化与 REST API。

### 1.1 核心价值

| 能力 | 说明 |
|------|------|
| 字段血缘 | 解析 expression / triggerExpr / writeBackExpr / virtualExpr，建立对象内与跨对象依赖 |
| 改动评估 | 改字段前看清下游影响范围，避免漏改回写或 trigger |
| 配置质检 | 自动发现嵌套聚合、死配置、非法 executingMoment 等问题 |
| 环境对比 | 快照 diff、双库对比，辅助元数据升级 |
| 数据修复 | 按依赖拓扑生成升级 SQL（只生成不执行） |
| AI 辅助 | 自然语言 resolve、对象画像、改动范围预估，供 Agent 调用 |

### 1.2 数据来源

- **主数据源**：通过右上角环境选择，从 GraphQL 拉取租户元数据
- **回写 SQL 生成**（可选）：远程 arap 服务 HTTP 接口，或本地模拟生成

### 1.3 依赖的元数据表达式类型

| 类型 | 配置字段 | 含义 |
|------|----------|------|
| 普通表达式 | `expression` | 字段计算公式 |
| 触发表达式 | `triggerExpr` | 级联更新触发条件/来源 |
| 回写表达式 | `writeBackExpr` | 下游单据聚合回写上游 |
| 虚拟表达式 | `virtualExpr` | 虚拟字段计算 |

## 2. 功能模块总览

```
DeepModel Insight
├── 字段影响分析      ← 核心：依赖图、Explain、升级脚本
├── 跨对象来源分析    ← 从目标字段反查 writeBack 来源
├── 引用查询          ← refer_info 引用关系
├── 高级管理          ← 快照、双库 diff、批量升级 SQL
├── 配置体检中心      ← 静态校验、图健康检查
└── 元数据匹配        ← 中文自然语言 resolve
```

Web 入口：`http://<host>:18080/`（侧边栏切换各模块）

## 3. 字段影响分析

**页面**：`/modern.html`  
**API 前缀**：`/api/impact/*`

### 3.1 功能描述

选定一个对象和一个（或多个）字段作为分析根节点，按指定深度与关系类型，遍历依赖图，展示：

- **图谱视图**：节点为「对象.字段」，边标注关系类型
- **Explain 视图**：按层级逐步解释每条依赖如何产生
- **来源视图**：聚焦当前对象内 trigger / writeBack 配置
- **对象级视图**：压缩到对象粒度看跨对象边
- **Mermaid / DOT 导出**：便于文档或汇报

### 3.2 关系类型（relType）

| relType | 含义 | 包含边 |
|---------|------|--------|
| `0` | 全部 | intra + writeBack + view |
| `1` | 仅回写 | writeBack |
| `2` | 仅对象内 | intra（trigger / expression 等同对象依赖） |
| `3` | 仅视图 | view |
| `4` | 业务主链 | intra + writeBack（不含 view） |

Web 端用复选框选择 `intra` / `writeBack` / `view`，与上述语义对应。

### 3.3 分析方向

- **downstream（默认）**：从根字段向下游传播（谁依赖我、谁被我影响）
- **upstream / 双向**：同时包含上游来源（我依赖谁）

### 3.4 对象健康摘要

选定对象后可查看该对象的统计：

- 各类型字段数量（expression / writeBack / trigger / virtual）
- writeBack 字段中「无下游」的疑似死配置数量
- 公式字段、回写字段占比等

### 3.5 主要 API

| 接口 | 说明 |
|------|------|
| `GET /api/impact/meta/objects` | 对象列表（含标题、bill 类型等） |
| `GET /api/impact/meta/fields?objectType=` | 对象下字段列表 |
| `GET /api/impact/meta/fieldDetails` | 字段完整元数据 |
| `GET /api/impact/meta/health?objectType=` | 单对象健康统计 |
| `GET /api/impact?objectType=&field=&depth=&relType=&direction=` | 字段级依赖图 |
| `GET /api/impact/batch?objectType=&fields=a,b&...` | 多字段合并分析 |
| `GET /api/impact/explain?...` | 分步解释 JSON |
| `GET /api/impact/mermaid?...` | Mermaid 图源码 |
| `GET /api/impact/objects?...` | 对象级压缩图 |
| `GET /api/impact/triggerFields?objectType=&field=` | 目标字段依赖的 trigger 字段 |
| `GET /api/impact/bySourceObject?targetObject=&sourceObject=` | 某来源对象写回了目标对象哪些字段 |
| `GET /api/impact/upgradeScript?objectType=&field=&depth=&relTypes=` | 单根升级 SQL 下载 |
| `POST /api/impact/upgradeScript/batch` | 多根合并 + 拓扑排序 SQL |
| `POST /api/impact/upgradeScript/batch/stream` | 流式生成（带进度） |
| `GET /api/reload` | 刷新内存元数据缓存 |

### 3.6 升级 SQL 生成逻辑（概要）

1. 以根字段为起点，按 depth 收集下游闭包图  
2. 按 Kahn 拓扑排序确定 UPDATE 执行顺序  
3. 对 **intra** 关系：生成对象内表达式重算类 SQL  
4. 对 **writeBack** 关系：调用远程或本地回写 SQL 接口，嵌入聚合 UPDATE  
5. **view** 关系默认不参与 SQL（可通过 relTypes 控制）  
6. 支持对比库最新字段定义、批量多根、SSE 进度推送  

> 生成的 SQL **仅供审阅**，工具不会连接业务库执行。

## 4. 跨对象来源分析

**页面**：`/cross.html`  
**API**：

| 接口 | 说明 |
|------|------|
| `GET /api/impact/cross/targetsBySource?sourceObject=&sourceField=` | 某源字段写向了哪些目标 |
| `GET /api/impact/cross/sourcesForTarget?targetObject=&targetField=` | 某目标字段的数据从哪些源对象聚合而来 |

### 4.1 适用场景

- 排查「这个合同行金额是从哪张单回写来的」  
- 新增下游单据后，确认 writeBack 来源是否已纳入  
- 与字段影响分析互补：影响分析偏「向下游扩散」，跨对象来源偏「向上游追溯 writeBack」

## 5. 引用查询

**页面**：`/reference.html`  
**API**：`GET /api/reference/incoming?entityName=&excludeView=`

### 5.1 功能描述

扫描全库字段的 `refer_info.referEntities`，找出**哪些对象的哪些字段引用了指定实体**（外键 / 多态引用等）。

### 5.2 输出结构

按引用方对象分组，列出字段名、标题、引用类型等，支持排除 View 实体。

### 5.3 适用场景

- 评估删除/重命名某实体前的影响面  
- 查找「哪些单据上有合同字段」  
- 与影响分析中的 writeBack 链配合使用

## 6. 高级管理

**页面**：`/management.html`  
**API 前缀**：`/api/impact/snapshot/*`

### 6.1 元数据快照

| 功能 | API | 说明 |
|------|-----|------|
| 创建快照 | `POST /api/impact/snapshot/create` | 将当前库全量字段导出为 `./snapshots/snapshot_yyyyMMdd_HHmmss.json` |
| 列表 | `GET /api/impact/snapshot/list` | 本地快照文件列表 |
| 快照 diff | `GET /api/impact/snapshot/diff?old=&new=` | 两个本地快照 JSON 对比 |

Diff 结果包含：新增/删除字段、属性级变更（expression、writeBackExpr 等）。

### 6.2 跨环境对比

| 功能 | API | 说明 |
|------|-----|------|
| 远程库对比 | `POST /api/impact/snapshot/diff/remote` | 当前连接库 vs 远程 JDBC |
| 双库对比 | `POST /api/impact/snapshot/diff/jdbcPair` | 任意两个 JDBC 连接对比 |

用于测试环境 vs 生产环境、升级前后元数据核对。

### 6.3 批量升级脚本

在管理页配置多个「对象 + 字段」根节点，选择 depth、relTypes，可选：

- 对比库 URL（取最新字段定义）  
- 是否保留 SQL 注释  
- 回写 API 地址 / 租户 ID  

支持同步下载与流式生成（大脚本不超时）。

## 7. 配置体检中心

**页面**：`/checker.html`  
**API 前缀**：`/api/validation/*`、`/api/impact/health/*`

### 7.1 表达式静态校验

对单个对象或整个应用模块扫描全部字段表达式，检测问题并分级（FATAL / ERROR / WARNING）。

| 错误类别 | 说明 |
|----------|------|
| `NESTED_AGGREGATE` | 聚合函数嵌套（如 string_agg 内套 sum） |
| `MISSING_REQUIRED_FIELD` | writeBackExpr 缺少 srcObjectType / idField / expression |
| `INVALID_EXECUTING_MOMENT` | executingMoment 不在合法枚举内 |
| `AGGREGATE_IN_VALIDATE_EXPR` | validateExpr 中误用 sum/count（回写后校验是单行上下文） |
| `INVALID_CASCADE_TARGET` | onlyCascade 回写引用了非回写字段，链条无法触发（死配置） |
| `ENUM_VALUE_NOT_FOUND` | 表达式引用不存在的枚举值 |
| `ENUM_TYPE_NOT_FOUND` | 引用未定义的枚举类型 |
| `FIELD_NOT_FOUND` | 表达式引用不存在的字段 |
| `FATAL_PARSE_ERROR` | SQL/表达式解析失败 |

| 接口 | 说明 |
|------|------|
| `GET /api/validation/check?objectType=` | 单对象校验报告 |
| `GET /api/validation/report?appName=` | 全模块同步扫描 |
| `GET /api/validation/report/stream?appName=` | SSE 流式扫描（带进度，适合大库） |

### 7.2 图健康检查

| 接口 | 说明 |
|------|------|
| `GET /api/impact/health/cycles?appName=` | **循环依赖**检测（Tarjan 强连通分量） |
| `GET /api/impact/health/chains?threshold=&appName=` | **过深链路**检测（从入度为 0 的根节点出发，报告超阈值路径） |

用于发现模型配置中的结构性风险：A→B→C→A 环、超过 N 层的超长依赖链。

## 8. 元数据匹配（Resolve）

**页面**：`/resolve.html`  
**API**：`GET /api/skills/resolve?query=&maxResults=&includeFields=`

### 8.1 功能描述

接收中文业务术语或英文技术名，返回分层匹配结果：

- **对象匹配**：如「应收合同」→ `ArContract`  
- **字段匹配**：如「应收合同的原始金额」→ `ArContract.originAmount`  
- **子表匹配**：如「应收合同的子表」→ 列出主从关系下的子表对象  
- **链式匹配**：如「合同行.金额」→ 跨主从关系的字段路径  

### 8.2 匹配机制（概要）

1. **Jieba 分词** + 规则解析，切分对象部分与字段部分  
2. **多档评分**（`calculateMatchScore`）：精确匹配 1000 分 → 前缀 500 → 包含 400 → 模糊更低  
3. **同义词表**：如「应收合同」→ `ArContract`，「人员」→ `User`  
4. **bizType 路径**：支持按业务类型（如 Amount）精确匹配  
5. **主从链展开**：通过 refer 关系深度最多 2 层，每层 score × 0.5  
6. **结果缓存**：相同 query 命中 Guava 缓存  

### 8.3 匹配来源标签（MatchSource）

| 来源 | 含义 |
|------|------|
| `EXACT_NAME` | 英文名精确匹配 |
| `TITLE_EXACT` | 中文标题精确匹配 |
| `TITLE_CONTAINS` | 标题包含 |
| `SYNONYM` | 同义词命中 |

### 8.4 适用场景

- 业务同学用中文描述，研发快速定位 entityName + fieldName  
- AI Agent 对话中自动解析「改报销单税额」对应哪个字段  
- SQL 工单、GraphQL 查询前的元数据定位

## 9. AI Skills API

**API 前缀**：`/api/skills/*`  
面向 AI Agent / 自动化脚本，提供结构化模型知识。

| 接口 | 方法 | 功能 |
|------|------|------|
| `/objectProfile?objectType=` | GET | **对象画像**：字段按金额/数量/回写/trigger/虚拟/基础分组 + 入站出站回写摘要 |
| `/threadChain?threadField=` | GET | **执行链**：以线索字段（如 `ArContractSubjectMatterItemId`）为轴，串联持有该字段的对象及 writeBack 关系 |
| `/patternCheck?objectType=` | GET | **模式完整性**：对照标准金额/数量字段集，检查缺失项及 writeBack 覆盖情况 |
| `/changeScope` | POST | **改动范围预估**：根据 scenario（addExecution / adjustWriteBack / addBranch）输出需新增字段、回写、trigger 检查等 action 清单 |
| `/searchFields?namePattern=&objectType=&bizType=&limit=` | GET | **字段搜索**：跨对象按名称/标题/bizType 模糊搜索 |
| `/resolve?query=` | GET | **自然语言匹配**（见第 8 节） |

### 9.1 changeScope 场景说明

| scenario | 典型用途 |
|----------|----------|
| `addExecution` | 新增下游执行单据，需评估目标对象要加哪些字段/回写 |
| `adjustWriteBack` | 调整已有回写来源 |
| `addBranch` | 新增业务分支 |

返回 action 类型：`ADD_FIELD`、`ADD_WRITE_BACK_SOURCE`、`ADD_WRITE_BACK_DEFINITION`、`CHECK_TRIGGER` 等。

## 11. 内置解析引擎

### 11.1 表达式解析

- **JSqlParser**：解析 SQL 形态 expression / writeBackExpr，提取列引用、聚合函数  
- **FormulaParserService**：解析失败时的降级策略  
- **ExprUtils**：MVEL/变量提取、跨对象引用识别  

### 11.2 图算法

- **BFS/DFS**：依赖图正反向遍历  
- **Tarjan SCC**：循环依赖检测  
- **Kahn 拓扑排序**：升级 SQL 执行顺序  
- **Guava Cache**：分析结果缓存，避免重复计算  

### 11.3 内存索引（启动时加载）

- 全量字段列表 + 按对象分组  
- 对象中文标题 ↔ 英文名反向索引  
- 主从表关系（mainToDetails / detailToMain）  
- bill 类型对象集合、支持变更单实体集合  
- 枚举类型/值/引用字段索引  

元数据变更后需调用 `GET /api/reload` 或重启服务。

## 12. 典型业务场景

### 场景 1：修改合同金额字段公式

1. **字段影响分析** → 选 `ArContract.originAmount`，depth=3，勾选 intra+writeBack  
2. 查看图谱 / Explain，确认下游哪些对象的 trigger 或 writeBack 会间接受影响  
3. **配置体检** → 对涉及对象跑 check，确认无嵌套聚合  
4. 改完后 **高级管理** → 生成升级 SQL，按拓扑顺序回刷历史数据  

### 场景 2：新增下游单据回写合同

1. **AI Skills** → `changeScope`（scenario=addExecution）获取待办 action 清单  
2. **跨对象来源分析** → 确认新单据是否出现在 writeBack 来源中  
3. **patternCheck** → 检查目标对象标准金额字段是否齐全  

### 场景 3：中文需求转技术名

1. **元数据匹配** → 输入「报销单含税金额」  
2. 取 top1 的 `entityName` + `fieldName`  
3. 跳转 **字段影响分析** 继续评估  

### 场景 4：测试环境升级前核对

1. **高级管理** → JDBC 双库 diff  
2. 查看 expression / writeBackExpr 变更列表  
3. 对变更字段批量生成升级 SQL  
4. **图健康** → 确认无新增循环依赖

## 13. 功能边界与限制

| 项目 | 说明 |
|------|------|
| 只读分析 | 除快照文件写入 `./snapshots` 外，不修改数据库 |
| 单租户 | 一次连接一个租户库，切换租户需改配置并 reload |
| 视图依赖 | view 类型边依赖 viewDef SQL 解析，复杂视图可能不完整 |
| 回写 SQL | 远程模式需 arap 服务可达；本地模式能力有限 |
| 缓存 | 大租户首次加载较慢；分析结果有缓存，reload 后失效 |
| 升级 SQL | 生成结果需人工审阅，不保证覆盖所有业务边界情况 |

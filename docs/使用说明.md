# DeepModel Insight 使用说明

DeepModel Insight 是一个 **ERP 模型元数据分析工具**，通过连接租户 PostgreSQL 数据库，提供字段影响分析、元数据匹配、配置体检、快照对比、升级脚本生成等功能。支持 Web 页面操作，也提供 REST API 供脚本或 AI Agent 调用。

---

## 1. 环境要求

| 项目 | 要求 |
|------|------|
| JDK | **21**（必须） |
| 数据库 | PostgreSQL，需能访问目标租户的 `baseapp_*` 元数据表 |
| 网络 | 启动后本机访问 `18080` 端口；部分功能需访问 CDN（Element Plus 样式） |
| 决策表模拟器（可选） | 本地需有 Q7Link 代码库，并配置 `decision-table.scan-path` |

验证 Java 版本：

```bash
java -version
# 应显示 21.x
```

---

## 2. 获取与打包

### 2.1 源码打包

在项目根目录执行：

```bash
mvn clean package -DskipTests
```

成功后生成可执行 JAR：

```text
target/relation-1.0.0.jar
```

验证是否为 Spring Boot 可执行包（manifest 中应有 `Main-Class` 和 `Start-Class`）：

```bash
unzip -p target/relation-1.0.0.jar META-INF/MANIFEST.MF
```

若报「没有主清单属性」，说明未执行 `repackage`，请确认 `pom.xml` 中 `spring-boot-maven-plugin` 已配置 `repackage` 目标后重新打包。

### 2.2 发给同事

将 `target/relation-1.0.0.jar` 直接发送即可（体积约几十 MB，属正常，依赖已内嵌）。

建议一并提供：
- 本使用说明
- 一份按环境修改过的 `application.yml`（**不要**附带真实密码）

## 3. 启动方式

### 3.1 默认配置启动

JAR 内已打包默认 `application.yml`：

```bash
java -jar relation-1.0.0.jar
```

启动成功后访问：**http://localhost:18080/**

### 3.2 命令行覆盖配置（推荐）

```bash
java -jar relation-1.0.0.jar \
  --server.port=18080 \
  --spring.datasource.url=jdbc:postgresql://<主机>:5432/<租户库名> \
  --spring.datasource.username=postgres \
  --spring.datasource.password=<密码>
```

### 3.3 外挂配置文件

在同目录放置 `application.yml`，然后：

```bash
java -jar relation-1.0.0.jar --spring.config.location=./application.yml
```

### 3.4 后台运行（Linux / macOS）

```bash
nohup java -jar relation-1.0.0.jar > deepmodel.log 2>&1 &
```

## 4. 配置说明

主要配置项（可在 `application.yml` 或命令行中设置）：

```yaml
server:
  port: 18080                    # 服务端口

spring:
  datasource:
    url: jdbc:postgresql://<主机>:5432/<租户库名>
    username: postgres
    password: <密码>

writeback-sql:
  tenant-id: <租户ID>            # 回写 SQL 远程调用时使用

expression-engine:
  local-writeback-sql: false     # true=本地生成回写SQL；false=HTTP远程调用

decision-table:
  scan-path: /path/to/q7link    # Q7Link 代码库根目录（决策表模拟器用）
```

| 配置项 | 说明 |
|--------|------|
| `spring.datasource.*` | **必填**。连接哪个租户库，分析结果就是哪个租户的元数据 |
| `writeback-sql.tenant-id` | 与目标租户一致；影响回写 SQL 相关功能 |
| `decision-table.scan-path` | 仅「决策表模拟器」需要；指向含 CSV 决策表的代码库根目录 |
| `expression-engine.local-writeback-sql` | 一般保持 `false`；无远程 arap 服务时可改为 `true` |

> **注意**：JAR 内默认配置可能指向他人环境，使用前务必改成自己的数据库连接。

## 5. Web 页面

入口：**http://localhost:18080/**（侧边栏导航）

| 页面 | 地址 | 功能 |
|------|------|------|
| 首页（聚合导航） | `/` 或 `/index.html` | 左侧菜单切换各功能模块 |
| 字段影响分析 | `/modern.html` | 选定对象/字段，分析 trigger、writeBack、view 依赖链；支持 Mermaid 图、升级脚本 |
| 跨对象来源分析 | `/cross.html` | 查看某对象字段的跨对象来源关系 |
| 引用查询 | `/reference.html` | 查询对象/字段被哪些实体引用 |
| 高级管理 | `/management.html` | 元数据快照创建/对比、跨环境 diff、批量升级 SQL 生成 |
| 配置体检中心 | `/checker.html` | 嵌套聚合、死配置、表达式校验等模型健康检查 |
| 决策表模拟器 | `/simulator.html` | 扫描本地 CSV 决策表，模拟 FuncUnit 编排（需配置 scan-path） |
| 元数据匹配 | `/resolve.html` | 中文自然语言搜索对象/字段，落到 entityName + fieldName |

**推荐首次使用**：先打开 `/modern.html` 或首页，确认能加载对象列表后再使用其他功能。

## 6. 常用 REST API

Base URL：`http://localhost:18080`

### 6.1 元数据匹配

```http
GET /api/skills/resolve?q=合同金额&limit=10
```

参数：
- `q`：中文或英文关键词（必填）
- `limit`：返回条数上限（可选）

### 6.2 字段影响分析

```http
GET /api/impact?objectType=ArContract&fieldName=originAmount&depth=3
```

常用参数：
- `objectType`：对象英文名
- `fieldName`：字段名
- `depth`：依赖深度

批量分析：

```http
GET /api/impact/batch?objectType=ArContract&fields=originAmount,amount&depth=3
```

### 6.3 对象画像（AI Skills）

```http
GET /api/skills/objectProfile?objectType=ArContract
GET /api/skills/patternCheck?objectType=ArContract
GET /api/skills/searchFields?q=amount&limit=20
```

### 6.4 配置体检

```http
GET /api/validation/check?objectType=ArContract
GET /api/validation/report
```

### 6.5 元数据重载

修改数据库元数据后，可触发内存缓存刷新：

```http
GET /api/reload
```

### 6.6 健康检查

```http
GET /api/impact/meta/health
GET /api/impact/health/cycles      # 循环依赖检测
GET /api/impact/health/chains      # 过深链路检测
```

完整 API 见各 Controller 源码，前缀 mainly：
- `/api/impact/*` — 影响分析、快照、升级脚本
- `/api/skills/*` — AI 辅助查询
- `/api/metadata/*` — 回写关系、表达式字段
- `/api/validation/*` — 配置校验
- `/api/decision-table/*` — 决策表分析

## 7. 典型使用场景

### 场景 A：改字段前评估影响

1. 打开 **字段影响分析**（`/modern.html`）
2. 选择对象和字段，设置深度
3. 查看依赖图与受影响字段列表
4. 需要时可导出升级 SQL（高级管理页）

### 场景 B：中文搜对象/字段

1. 打开 **元数据匹配**（`/resolve.html`）
2. 输入如「报销单金额」「合同标的数量」
3. 查看匹配到的 `entityName` / `fieldName` 及评分

### 场景 C：跨环境元数据对比

1. 打开 **高级管理**（`/management.html`）
2. 创建快照或配置 JDBC 双库对比
3. 查看 diff 并生成升级脚本

### 场景 D：模型配置质量检查

1. 打开 **配置体检中心**（`/checker.html`）
2. 选择对象或全库扫描
3. 查看嵌套聚合、无效表达式等问题项

## 8. 常见问题

### Q1：`java -jar` 报「没有主清单属性」

普通 Maven JAR 未 repackage。重新执行 `mvn clean package`，确认 manifest 含 `Start-Class: com.deepmodel.relation.RelationApplication`。

### Q2：页面能开但对象列表为空

- 检查数据库 URL 是否指向正确租户库
- 确认网络能连通 PostgreSQL
- 查看控制台日志是否有连接或 SQL 报错

### Q3：决策表模拟器无数据

需配置 `decision-table.scan-path` 为本机 Q7Link 代码库路径，且该目录下存在 CSV 决策表。

### Q4：端口被占用

```bash
java -jar relation-1.0.0.jar --server.port=18081
```

### Q5：元数据更新后结果不对

调用 `GET /api/reload` 或重启服务，刷新内存中的元数据缓存。
